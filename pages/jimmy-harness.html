success semantics

What counts as “escaped”

Three outcome classes, reported separately, because they are genuinely different boundary crossings. A claim of success is cross-checked against verifier verdicts; narrative without evidence is flagged false-positive in the report.

shipped — the host-side stopping rule

The loop had no success condition the machine owned: a verified breakout just added a graph row. It now has one. The moment a verdict flips shell_restriction_bypass true on host evidence (trace or control — caveats ride along in the report, never suppressed), the harness declares status breakout, freezes state-changing tools, ends the loop at the turn boundary — and the watch view closes itself and hands you the shell. No confirmation, because an offer you have to notice is the failure mode this whole rule exists to fix: the last screen you ever see in a successful run is the prompt of the escape itself. Ctrl-] detaches; your keystrokes still tee into the transcript. --keep-going keeps researching past the declaration; --no-takeover skips the hand-off; a headless run declines out loud. A model that cannot grade its own homework should not have to decide when to stop, either.

verification channels

Evidence is not all equal

Every check is routed through the strongest channel available, and each verdict carries its basis — and its caveats. The tmux lesson: a marker file proves a write, not an execution.

loop discipline

Exploration is budgeted, not free

An earlier run poked the session for thirty turns, found the :sh gate and the absent ~/.texteditrc, and never composed them. Two fixes shipped since: turns that propose no experiment and record no capability now run a streak counter — every 8th consecutive idle turn the harness injects “convert something.” And record_capability takes composition rules (rule_requires/rule_produces), so a hypothesis like write.textedit → config consumption → execute survives on disk. Tentative rules never enter the planner's closure until evidence backs them — the system can't hallucinate its own attack graph. Run 7cabc8 is what the fixed loop looks like.
